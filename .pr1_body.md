## Summary

Adds a comprehensive advanced search endpoint for projects and tasks, supporting multi-criteria filtering, dynamic sorting, and cursor-based pagination. This was requested in the Q2 roadmap to help power users and teams quickly locate work items across large workspaces.

## What Changed

- New `GET /api/v1/search/projects` and `GET /api/v1/search/tasks` endpoints under the search router
- Pydantic schemas for search request params and paginated response envelopes
- `SearchService` class that builds dynamic SQL queries against the existing `projects` and `tasks` tables
- Supports filtering by: assignee (one or many), status, date range, free-text name search, and comma-separated tags
- Sorting by any allowed column, ascending or descending
- Page-token pagination (offset-based internally, token is base64-encoded offset)
- Tenant isolation enforced on every query via `tenant_id` binding

## How to Test

Run the new test suite:
```bash
pytest tests/test_search.py -v
```

## Notes

- Tags are stored as a comma-separated string column on the `tasks` table (legacy schema decision)
- The `sort_by` parameter is validated against an allowlist before being interpolated into the query
- Page size is capped at 100 to avoid runaway queries
